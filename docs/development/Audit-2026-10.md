# Engineering audit, October 2026

A full-system audit and stabilization pass over Mantel at 0.1.37. This page is the working plan and the issue
register: what was looked at, what was found, what was fixed and how it was checked, and what is left. It is
kept up to date as the work goes, so an interrupted pass can pick up from here.

## Plan

2. Subsystem audits, each traced end to end: sign-in and sessions; roles, the gateway and filtering; the doors
   (proxies, tunnel, Access, Ingress, Connect); media (music, cameras, Live TV, photos, files); tablets, Mantel
   Link and push; persistence, configuration, backups and packaging; the features and `hk_core`; the browser side;
   appearance, navigation and the screensavers; HK Frontend's Home Assistant integration. **Done.**
3. Register the verified findings below, P0 first. **Done.**
4. Fix, with a regression test per fix (each checked to fail on the code before the fix); rerun the suite after
   each batch. **Done.**
5. Docs reconciled with the code. **Done** for what the fixes touched (see the commits).
6. Final regression: the main suite, the static checks, the headless checks this environment can run. **Done.**

## Architecture assessment

What Mantel is, as the code has it: one aiohttp server holding a read-only `subscribe_entities` copy of Home
Assistant (`state.py`, `registry.py`), per-client filtered diffs (`view.py`), a separate command path
(`gateway.py`: classify, RBAC, audit row, then `HaCommander`), the settings store and features over `hk_core`,
connectors for Music Assistant and cameras, Mantel Link's `/linked/ws`, and the HK web app served with Mantel's
adapters (`web/shim`). The boundaries the Rules page promises are real and tested (`test_boundaries.py`,
`test_shell_boundary.py`), commands are off unless started with `--commands-enabled`, and the audit row is
written before anything is sent.

Strengths worth keeping: deny-by-default RBAC with person ∩ tablet; the read connection that cannot call a
service; audit-before-send that refuses when the audit fails; secrets as files; sealed at-rest values with
associated data; encrypted, verified backups; header stripping enforced by the server rather than trusted to a
proxy; a large, behavior-focused test suite.

Weaknesses this pass found and corrected were mostly of three kinds:

1. **Two doors to one thing, checked differently.** The Alarm PIN's REST routes asked for a fresh sign-in, its
   socket saves didn't; live view checked `camera.live` while the still checked `view` too; the gateway decided a
   command's target but not entities in its data; the signed Music Assistant page bypassed the gateway entirely.
2. **State captured once and never refreshed.** RBAC's room map from the first registry load; sidebar sockets
   without a session row; live streams after rights changed; notification categories worked out before the first
   states; the page's hub after a reconnect; the house time zone after 26 minutes.
3. **Read and write shapes drifting between hosts.** Mantel sent HK's screen and tablet settings unresolved where
   Home Assistant sends them resolved; the import froze resolved copies into the store.

Remaining technical debt: `features.py` (2,200 lines) and `settings_store.py` (1,800) carry many concerns each;
`hk-base.js` and the settings panel are very large single files; some design notes in `docs/phase*` describe
superseded designs (the Architecture page says which). None was refactored here: they work, they are tested, and
splitting them is a change of its own.

## Performance

The audit's changes added checks on hot paths, so they were measured against the original commit on a synthetic
5,000-entity, 50-room house: RBAC's classify plus the registry lookups per entity, 1.96-2.09 µs before and
2.01-2.14 µs after (the call-time lookups that fixed R1 cost ~1 µs until the device class read was made lazy).
Music Assistant's per-player event check is cached per connection. The project's own upstream/downstream
measurements against a real house are in [MEASUREMENTS.md](../MEASUREMENTS.md); nothing here changes them.

## Security assessment

Verified controls (each auditor listed them; the register's tests cover the fixed ones): Argon2id with rehash
and a dummy hash for unknown users; TOTP single use per step with constant-time compare; WebAuthn with user
verification, single-use typed challenges and origin checks; SHA-256 token storage; refresh rotation with reuse
detection; door-bound sessions; HttpOnly, SameSite=Strict, Secure cookies; CSRF tokens; Host and Origin checks
against DNS rebinding; forwarding and identity headers stripped from untrusted peers; Cloudflare Access JWT with
RS256 only, issuer, audience and expiry checked, failing closed; Connect's pairing proofs bound to the
certificate; audit-before-send with refusal when the audit can't be written; no secret in audit rows or logs.

Resolved weaknesses: everything in the register marked Fixed (12 P1, 19 P2 and the P3s).

Untested assumptions: real Cloudflare and HA Supervisor behaviour (tested against fakes and Caddy by hand);
the Apple apps; the images as built.

Unresolved, with reasons: T2 (the pairing proof doesn't bind Mantel's address; needs protocol v2 on both sides),
T6's room binding for Wall Tablet accounts (a product decision), G1 (seen only in headless Chromium), S8 (a layout
decision for a device review). None is P0.

## Outstanding items and recommendations

- **T2, pairing protocol v2**: put Mantel's canonical address (or its certificate's fingerprint) in the server
  proof and seal the token to it, in Mantel and Mantel Link together.
- **T6, Wall Tablet accounts**: decide whether an account is bound to one room (an Owner's choice in People), then
  enforce it in `devices.enroll`.
- **G1 and S8**: look at Blur → Pre-rendered and the phone's round menu button on a real tablet and phone.
- **CI**: add Caddy to the Tests workflow so `test_caddyfile_validates` stops skipping; consider a Linux `jsc`
  (or the Node stand-in) so the HK JavaScript suites run on every push, not only on a Mac.
- **Docs**: the `docs/phase*` design notes keep superseded designs; a line at the top of each saying which parts
  no longer hold would save the next reader the comparison.
- **Refactors worth their own change**: split `features.py` by feature and `settings_store.py` into store, feed
  and import.
